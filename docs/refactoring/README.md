# План рефакторинга Opeks

Документ описывает рефакторинг Discord-бота **Opeks** (TypeScript + discord.js v14).
Цель — не менять технологии, а навести порядок: вынести чувствительные данные и
константы в конфиг/ENV, убрать костыли и слабые места, перевести код на классы и
принципы SOLID, устранить дублирование и повысить общее качество.

> ⚠️ На текущем этапе **правки кода не вносятся**. Этот каталог — только план.

## Резюме (кратко)

### Что хорошо
- Чёткое разделение по слоям: `commands` / `listeners` / `parsers` / `custom` / `config`.
- Единый тип `Command` и интерфейс `TextParser` — регистрация через массивы (`Commands`, `Parsers`).
- Локализации (ru/uk) у команд и опций.
- Конфигурация уже вынесена в `.env` и валидируется на старте.

### Главные проблемы
1. **Чувствительные данные и константы захардкожены** в коде: ID серверов/пользователей,
   имена ролей/каналов, URL вики и API, модель и параметры LLM, «магические числа».
2. **Дублирование**: логика обращения к Fandom-вики в 3 файлах (`Wiki.ts`, `WikiLinks.ts`,
   `Verdict.ts`), `callLLM` в 2 файлах, блоки опций `option_1..option_10` в 2 командах.
3. **Слабые места**: избыточные `as`/`!`-касты, необработанные `null`/`undefined`
   (баг в `Sauce.ts`), `while`-цикл без гарантии выхода в `Special.ts`, «мёртвый» код
   (`Embed.ts`, карта `texts` в `Nekoslife.ts`, кнопка в `Tracemoe.ts`).
4. **Нет классов/SOLID**: команды, парсеры и слушатели — плоские объекты/функции.
5. **Нет инфраструктуры качества**: сборки (только `ts-node` на старте), линтера,
   форматтера, логгера, тестов, `.env.example`.

### Целевой итог
Переход на: валидируемый конфиг + централизованные константы; базовые абстрактные
классы для команд/парсеров/слушателей; выделенные сервисы (Wiki, LLM/OpenRouter,
SauceNAO, TraceMoe, Nekos); хелперы (`random`, `time`, `embed`, `footer`); единый
логгер и обработчик ошибок; сборка в `dist` вместо `ts-node` в проде.
